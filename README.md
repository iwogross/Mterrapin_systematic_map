# Mterrapin_systematic_map

Code and extraction resources for the systematic map of diamondback terrapin (*Malaclemys terrapin*) literature, registered as a Stage 1 Registered Report at *Ecological Solutions and Evidence*.

**OSF:** 10.17605/OSF.IO/RSX7G 
**Stage 1 protocol:** DOI TBD


## Repository structure

```
Mterrapin_systematic_map/
├── Mterrapin_systematic_map.Rproj
├── R/
│   ├── batch_maker.R              Build NotebookLM extraction batches
│   └── fuse_notebook.R            Fuse NotebookLM outputs per batch
├── notebooklm_resources/
│   ├── 00_extraction_protocol.md  Task, output structure, CSV rules
│   ├── 01_module_registry.csv     Generated by batch_maker.R*
│   ├── 02_flag_schema.csv         Manual-review flag types and severity
│   ├── 03_codebook.csv            Variable-level coding authority
│   └── 05_general_coding_rules.md Cross-variable conventions
├── benchmarks/
│   ├── 06_benchmark_extraction.csv  Human extractions of benchmark studies
│   └── *.pdf                        Benchmark PDFs*
├── Included/                      Full-text PDFs*
├── notebooklm_batches/            Batch manifests, prompts, run logs*
├── notebook_outputs/              Raw NotebookLM CSV outputs*
└── fused_extractions/             Fused workbooks for manual review*
```

\* Not tracked. PDFs are copyrighted; all other marked files are regenerated by the scripts or by NotebookLM.

## Workflow

1. Place included full-text PDFs in `Included/`. File names (lowercased, without extension) become `study_ID`. Scanned PDFs must be OCRed first; `batch_maker.R` warns about any PDF with little or no text layer and lists them in `text_layer_check.csv`.
2. Open `Mterrapin_systematic_map.Rproj` and run `R/batch_maker.R`. This derives `01_module_registry.csv` from the codebook, splits PDFs into batches of 10, and writes a manifest and one runner prompt per codebook module for each batch.
3. For each batch, upload the contents of `notebooklm_batches/<batch_id>/upload_to_notebooklm/` to a new NotebookLM notebook and run the prompts in `prompts/` in module order, all in one chat. The last prompt is a review step: NotebookLM rates its own extraction of each study across all earlier modules (`extractor_confidence`), so it must see those outputs in the chat history.
4. Save each module's two CSV outputs unedited to `notebook_outputs/<batch>/` as `<batch>_<module>.csv` and `<batch>_<module>_flag.csv` (e.g. `b001_3.csv`, `b001_3_flag.csv`).
5. Run `R/fuse_notebook.R`. For each batch it repairs known NotebookLM CSV formatting errors, joins module outputs on `batch_id`, `source_document_name` and `study_ID`, and writes `fused_extractions/<batch_id>_fused_extraction.xlsx`.
6. Resolve flagged records by manual review against `02_flag_schema.csv`.

### Provenance

`batch_maker.R` writes `run_log.csv` (MD5 checksums of the codebook, protocol, flag schema, coding rules and benchmark files) and `session_info.txt` to `notebooklm_batches/`. `fuse_notebook.R` takes `run_id` from each batch manifest, so every fused record traces back to the resource versions and prompts used to extract it.

These generated files are not tracked in this repository.

Each fused workbook contains:

| Sheet | Contents |
|---|---|
| `extraction_fused` | One row per study, all modules joined |
| `manual_review_flags` | All flags across modules |
| `coverage_check` | Manifest studies vs. extracted studies, including `study_ID` mismatches |
| `module_output_check` | Missing, unexpected and out-of-order variables per module, against the codebook |
| `file_inventory` | Input CSVs and their parsed module numbers |
| `duplicate_key_check` | Studies with more than one row after joining |
| `module_registry` | Module definitions used |

## Reproducing the environment

Package versions are recorded with `renv`:

```r
install.packages("renv")
renv::restore()
```

Required packages: `here`, `fs`, `dplyr`, `purrr`, `readr`, `stringr`, `tibble`, `glue`, `openxlsx`, `pdftools`. Developed with R 4.5.

## Data availability

Full-text PDFs, including benchmark PDFs, are copyrighted and are not redistributed. The list of included and benchmark studies, with DOIs, is provided in [TBD following stage 2 publication] and `benchmarks/06_benchmark_extraction.csv`, respectively.

`benchmarks/06_benchmark_extraction.csv` holds human extractions of the benchmark studies, currently the 20 pilot studies. Benchmark PDFs placed in `benchmarks/` are uploaded with every batch alongside this file as worked examples of the expected output.
